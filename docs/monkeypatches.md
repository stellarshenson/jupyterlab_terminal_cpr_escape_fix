# Monkey patch register

Every upstream attribute that this extension replaces, with the way to check whether upstream still needs the patch. The table in [README.md](../README.md) is the short form of this register.

- Server patches replace attributes of `jupyter_server_terminals.handlers.TermSocket` in `_load_jupyter_server_extension` in `jupyterlab_terminal_cpr_escape_fix/__init__.py`; the assignment creates the attribute on that class. Before the patch, `TermSocket.open` resolves to `jupyter_server.base.websocket.WebSocketMixin.open` (MRO: `TermSocket`, `TerminalsMixin`, `ExtensionHandlerMixin`, `WebSocketMixin`, `JupyterHandler`, `AuthenticatedHandler`, `terminado.websocket.TermSocket`, ...), which starts the ping callback and calls `super().open()`, which reaches `terminado.websocket.TermSocket.open`; `TermSocket.on_pty_read` resolves to `terminado.websocket.TermSocket.on_pty_read`
- MP-2, MP-3, MP-4 and MP-5 share one replacement of `TermSocket.open` (`_patched_open`); it is installed when at least one of `suppress_buffer_replay`, `repaint_on_attach`, `strip_replay_queries`, `clear_before_replay` is on
- Server switches are keys of `DEFAULTS` in `__init__.py`; a test run overrides one with `CPR_FIX_DEFAULTS='{"key": false}'` (read by `ui-tests/jupyter_server_test_config.py`, an unknown key stops the server)
- A canary is a test that fails while the patch is switched off; a canary that passes with its switch off means upstream no longer needs the patch
- Test-only patches, not part of the extension: `ui-tests/jupyter_server_test_config.py` wraps `TermSocket.open`, `TermSocket.on_message` and `ptyprocess.PtyProcess.setwinsize` to write a server-side event log, active only when `TERMINAL_WATCH_FILE` is set
- Upstream versions last checked on 2026-10-12: terminado 0.18.1, jupyter_server_terminals 0.5.4, jupyter_server 2.21.1, JupyterLab 4.6.4 (Python package); the served frontend bundle (`/opt/conda/share/jupyter/lab/static/third-party-licenses.json`) holds `@jupyterlab/terminal` 4.6.4, `@jupyterlab/services` 7.6.4, `@xterm/xterm` 5.5.0 and `@xterm/addon-fit` 0.10.0; `node_modules` holds the build-time copies `@jupyterlab/terminal` 4.5.11 and `@jupyterlab/services` 7.5.11 with the same xterm versions

## How to check against upstream

After an upgrade of terminado, jupyter_server_terminals, JupyterLab or xterm.js, run each canary with its switch off. A canary that passes means the patch can be retired with the removal steps of its entry. A canary that fails means the patch is still needed. Run from `ui-tests/` with a free port in 8901 to 8905 (never 8888). A logged run puts `set -o pipefail;` in front of the command and `2>&1 | tee ../logs/<log>` behind it; `<log>` is a file in `logs/`.

## MP-1 Reply filter

- Replaced attribute: package `jupyter_server_terminals`, class `handlers.TermSocket`, attribute `on_pty_read`; assigned on the class, wrapping the inherited `terminado.websocket.TermSocket.on_pty_read`
- Installed by: `_load_jupyter_server_extension` in `jupyterlab_terminal_cpr_escape_fix/__init__.py` (`TermSocket.on_pty_read = _filtered_on_pty_read`); the patterns are in `jupyterlab_terminal_cpr_escape_fix/handlers.py` (`filter_terminal_responses`, `FILTER_PATTERNS`)
- What it does: removes terminal query replies (CPR, DA, DA2, DECRPM, OSC colour replies, and the same replies with the ESC byte stripped by fish) from all output sent to the browser, live output and replay; why: the replies would appear as literal text at the shell prompt; criteria section FILTER in `docs/acc-crit.md`; defects DEF-FILTER-8, DEF-FILTER-9 and DEF-FILTER-11 are defects of this filter
- Switch: none for the filter as a whole; `DEFAULTS['filter_osc_color_responses']` (default on, `__init__.py`) removes the pattern `bare_osc` from `FILTER_PATTERNS` when off
- Canary: none; no switch turns the filter off, and no committed functional test fails with `bare_osc` removed (not verified by a run)
- Retire when: terminado or JupyterLab stops handing terminal replies to the shell as typed text, so that a lab terminal never shows them; not verified how to observe this without the filter
- Removal steps: delete the `_original_on_pty_read`, `_filtered_on_pty_read`, `_flush_log` block and the assignment `TermSocket.on_pty_read = ...` in `__init__.py`; delete `FILTER_PATTERNS` use and `filter_terminal_responses` in `handlers.py` and the key `filter_osc_color_responses`; delete the imports of `filter_terminal_responses` and `FILTER_PATTERNS` in the `from .handlers import` line of `_load_jupyter_server_extension` in `__init__.py`, `tests/test_handlers.py:3` and `tests/test_replay_clear.py:12`; replay steps that call `type(self).on_pty_read` then reach the inherited method; delete the classes `TestFilterEscPrefixed`, `TestFilterBareSequences`, `TestFilterMixed` and `TestSequenceComplement` in `tests/test_handlers.py` and `test_prefix_survives_response_filter_with_replies_in_replay` and `test_response_filter_leaves_prefix_intact` in `tests/test_replay_clear.py`; delete the README paragraph and the row MP-1; steps not run as a drill

## MP-5 Repaint on attach

- Replaced attribute: same as MP-2 (`TermSocket.open`, shared wrapper `_patched_open`); after the original `open` returns, the wrapper schedules a PTY size step (one column narrower for 0.12 s, then the original size) with `IOLoop.call_later`
- Installed by: `__init__.py` (`_patched_open`, `_make_winsize_bounce`, `_shell_at_prompt`, the frozenset `_SHELLS`, constants `_BOUNCE_DELAY`, `_BOUNCE_STEP`, `_BOUNCE_DEBOUNCE`)
- What it does: sets the PTY to `(rows, cols - 1)` 0.4 s after a client attaches and back to `(rows, cols)` 0.12 s later, so the kernel sends SIGWINCH to the foreground process group twice and a full-screen program repaints; the restore write runs only while the PTY still has the stepped size; no step while the foreground process group of the terminal is one shell alone, which the server treats as a shell at its prompt (`_shell_at_prompt`: the bytes of `/proc/<os.tcgetpgrp(fd)>/comm` are one of `bash`, `sh`, `dash`, `zsh`, `fish`, `ksh`, `tcsh`, `csh`, and no pid in `/proc/<pid>/task/<pid>/children` of that leader has the leader's process group), because a shell at its prompt needs no repaint; a shell with a child in its own process group is stepped, because it runs a program without job control (`sh -c`, `bash <script>`) and that program needs the repaint; a child in another process group (a background job) does not count; why: the replay holds only incremental frames, so static regions of a refreshed browser stay missing; criteria section BOUNCE in `docs/acc-crit.md`
- Step history: until 2026-10-12 the step was one row taller; a program that addresses rows absolutely on the normal buffer then wrote one row below the browser's last row and lost the line it committed during the step (DEF-BOUNCE-14, 10 of 10 page reloads damaged under stress in E5);
