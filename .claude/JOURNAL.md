6. **Task - Fix bare sequence filtering** (v0.9.18): Root-caused and fixed why CPR sequences leaked through the filter<br>
   **Result**: Built PTY simulation scripts (`test_pty_raw.py`) to reproduce the issue in isolation. Discovered that fish shell strips the ESC byte (`\x1b`) from terminal query responses and echoes the remainder as bare text - so `\x1b[2;1R` becomes `[2;1R` in PTY output. The regex `\x1b\[\d+;\d+R` requires the ESC prefix and never matched. Added 4 bare-pattern regexes with negative lookbehind `(?<!\x1b)` for CPR, DA, DA2, and DECRPM to filter sequences both with and without ESC prefix. Normal bracket usage (`array[0]`) is preserved because bare patterns require terminal-specific suffixes (`;digitR`, `;digitc`, `$y`). All 21 unit tests pass including tests for actual fish shell PTY output patterns.

12. **Task - Preserve terminal queries** (v1.0.5+): Fixed filter stripping outgoing terminal capability queries, breaking negotiation<br>
    **Result**: Log analysis revealed filter was removing `\x1b[>c` (DA2 query), `\x1b]10;?\x07`, `\x1b]11;?\x07` (OSC color queries) - these are shell-to-terminal requests, not terminal-to-shell responses. Stripping them prevented xterm.js from receiving queries and thus from responding, likely contributing to loops that produce bare response artifacts. Tightened regexes to distinguish queries from responses: `ESC_DA` now requires digit after `?` (`\[\?\d+[\d;]*c`), `ESC_DA2` requires at least two numeric params with semicolon (`\[>\d+;\d+[\d;]*c`), `ESC_OSC` excludes `;?` prefix via negative lookahead. Added 6 complement tests for query preservation (OSC 10/11/12, DA/DA2). Total 58 tests passing.
