6. **Task - Fix bare sequence filtering** (v0.9.18): Root-caused and fixed why CPR sequences leaked through the filter<br>
   **Result**: Built PTY simulation scripts (`test_pty_raw.py`) to reproduce the issue in isolation. Discovered that fish shell strips the ESC byte (`\x1b`) from terminal query responses and echoes the remainder as bare text - so `\x1b[2;1R` becomes `[2;1R` in PTY output. The regex `\x1b\[\d+;\d+R` requires the ESC prefix and never matched. Added 4 bare-pattern regexes with negative lookbehind `(?<!\x1b)` for CPR, DA, DA2, and DECRPM to filter sequences both with and without ESC prefix. Normal bracket usage (`array[0]`) is preserved because bare patterns require terminal-specific suffixes (`;digitR`, `;digitc`, `$y`). All 21 unit tests pass including tests for actual fish shell PTY output patterns.

12. **Task - Preserve terminal queries** (v1.0.5+): Fixed filter stripping outgoing terminal capability queries, breaking negotiation<br>
    **Result**: Log analysis revealed filter was removing `\x1b[>c` (DA2 query), `\x1b]10;?\x07`, `\x1b]11;?\x07` (OSC color queries) - these are shell-to-terminal requests, not terminal-to-shell responses. Stripping them prevented xterm.js from receiving queries and thus from responding, likely contributing to loops that produce bare response artifacts. Tightened regexes to distinguish queries from responses: `ESC_DA` now requires digit after `?` (`\[\?\d+[\d;]*c`), `ESC_DA2` requires at least two numeric params with semicolon (`\[>\d+;\d+[\d;]*c`), `ESC_OSC` excludes `;?` prefix via negative lookahead. Added 6 complement tests for query preservation (OSC 10/11/12, DA/DA2). Total 58 tests passing.

13. **Task - Buffer replay suppression** (v1.0.6): Fixed terminal MOTD/prompt duplication when returning to idle terminal after WebSocket reconnection<br>
    **Result**: Root-caused to terminado's `TermSocket.open()` draining `read_buffer` (deque maxlen=1000 of historical PTY output) through `on_pty_read` on every WebSocket reconnect. JupyterLab's xterm.js retains content across reconnections so the replay duplicates MOTD and prompts. Traced full MRO chain: `WebSocketMixin.open` -> `terminado.TermSocket.open` (buffer drain) -> `tornado.WebSocketHandler.open`. Patched `TermSocket.open` in `__init__.py` with `_no_replay_open` that sets instance-level `self.on_pty_read = lambda text: None` before calling original `open()`, then deletes the instance attribute to restore class method lookup for live PTY output. Added 2 unit tests (`TestBufferReplaySuppression`) verifying suppression during open and restoration after. All 60 tests pass.

14. **Task - Buffer replay toggle** (v1.0.8): Made buffer replay suppression a toggleable default, disabled by default<br>
    **Result**: Buffer replay suppression (entry #13) caused side effects in some environments where terminado's buffer replay is actually needed for terminal state recovery after reconnection. Rather than removing the feature entirely, added `DEFAULTS` dictionary at module level in `__init__.py` with `suppress_buffer_replay: False` key. The `TermSocket.open` patch now only applies when toggle is `True` - CPR filter patch always applies regardless. Startup log message dynamically lists active patches based on which toggles are enabled. Tests for the suppression mechanism retained in `TestBufferReplaySuppression` class - they test the mechanism directly, independent of the toggle. All 60 tests pass.

15. **Task - Bare OSC color filter and acceptance docs**: Filtered bare OSC color responses leaking on reconnect, added internal toggle and acceptance criteria doc<br>
    **Result**: Live diagnosis against installed 1.0.9 fed the exact leaked fish bytes through `filter_terminal_responses()` and proved CPR/DA/DA2/DECRPM bare remnants were stripped but OSC color responses leaked as literal `]10;rgb:..\` and `]11;rgb:..\`. Root cause: fish strips ESC from both the `]` introducer and the ST terminator, and `handlers.py` had only the ESC-prefixed `ESC_OSC`, no bare equivalent. Added `BARE_OSC = re.compile(r'(?<!\x1b)\](?:4|10|11|12);(?:\d+;)?rgb:[0-9a-fA-F/]+(?:\x07|\\))')` - `rgb:`-anchored to keep the false-positive surface near zero - and registered it as `('bare_osc', BARE_OSC)` in `FILTER_PATTERNS`. Gated behind new `DEFAULTS['filter_osc_color_responses']` (default `True`) in `__init__.py`; when `False`, `_load_jupyter_server_extension` drops the `bare_osc` entry before patching. Added 7 tests (3 filter, 1 full-leak, 3 protection proving plain `]10;` text, `]N;?` queries and ESC-prefixed OSC are untouched), total now 67 passing. Created `docs/ACCEPTANCE_CRITERIA.md` mapping every filter and protection criterion to its enforcing test. Checkpoint tag `CHECKPOINT_BEFORE_BARE_OSC_FIX_1.0.9` cut and pushed before implementation.
